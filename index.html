Three approaches

SVD, KNN, EASE — same problem, different math.

Each algorithm is implemented and evaluated on the same MovieLens-100K split. The from-scratch EASE uses the closed-form solution; SVD and KNN go through the Surprise library.

Best RMSE

SVD — Matrix Factorization

Discovers ~50 latent factors that explain user × movie preferences. The workhorse of modern recommenders.

R ≈ U · Σ · VT
Most explainable

KNN — Neighborhood

Find the k most similar users (or items) by cosine similarity, then predict by weighted average. Slow at scale, but every recommendation has a clear "why".

r̂u,i = Σ sim · r / Σ sim
Surprisingly competitive

EASE — Closed-form

A single linear system: B = (XTX + λI)−1 with diag(B)=0. No iterations, no hyperparameters except λ.

Implemented from scratch — see notebook

EASE (from-scratch implementation)

EASE was implemented from scratch following Steck 2019 — closed-form item-item solution with λ-regularized Gram inverse and the critical diag(B) = 0 step (so items can't recommend themselves). Trained on the implicit-feedback version of MovieLens-100K (all positive ratings → 1), which is the formulation the paper actually uses, so RMSE on explicit ratings isn't the right metric here. The notebook validates EASE by inspecting recommended items per user; the similarity matrix has 99.94% non-zero density and prediction scores in [-0.47, 1.35]. A proper hit-rate / NDCG@K evaluation would be the honest benchmark — that's on the "needs work" list.

Honesty

What this project is — and what it isn't.

Course portfolio piece. Two months of work. Real implementations, real evaluation, but real limits worth naming up-front.

✓ Real

  • SVD, KNN, EASE implementations work on real MovieLens-100K data
  • EASE is implemented from scratch with the correct diag(B)=0 step
  • Cross-validation results match published baselines
  • Open-source — every number is reproducible from the notebook

✗ Not real

  • The in-browser demo is the prediction formula, not a deployed model
  • RMSE 0.6757 was a single lucky split; the honest number is the CV ~0.9452
  • No cold-start handling beyond what the libraries provide out of the box
  • No implicit feedback, no temporal dynamics, no production serving stack

What I'd do next

Add ranking metrics

Precision@k and recall@k matter more than RMSE for top-N recommendation. The notebook code is there — just needs the eval loop.

Compare to neural CF

Train a small two-tower model with PyTorch and put it head-to-head with EASE. The literature suggests EASE will hold up surprisingly well.

Cold-start strategy

Hybrid with content features (genre, year, cast) for users with <5 ratings — the current eval drops them silently.
